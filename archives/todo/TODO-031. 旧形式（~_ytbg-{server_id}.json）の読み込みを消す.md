- main のモデルは、この項目を含む一連の作業で Opus 5 / effort high に
  していた（見込みの Sonnet 5 / medium から上書き）
- **reviewer は見込みに無かったが足した。** 分岐を 1 つ消す変更なので、
  `~/.claude/CLAUDE.md` の「挙動が変わる項目にはレビューの担当も入れる」に従った
- verifier は定義（`~/.claude/agents/verifier.md`）のまま

## きっかけ

TODO-024 で保存を JSON Lines（`~/ytbg-{server_id}.jsonl`）へ移した。
`.jsonl` が無いときだけ旧形式（`.json`）を読む互換の経路を残していたが、
移行が済んだら消すと決めていた。

## 決めたこと

- **いつ消すか**: 手元の 4 つのボードが、1 回でも `.jsonl` で正常に保存・
  再起動できれば着手してよい。長く待たない
- **旧ファイル（`.json`）そのものは残す**。読み込みコードだけ消す

## やったこと

### 移行（着手条件を満たす）

`Storage` で `.json` を読んで `.jsonl` へ書き出し、書いたものを読み直して
内容が一致することを確かめた。

| server_id | 履歴 | 進む側 |
|-----------|------|--------|
| 1 | 89 件 | 0 件 |
| 2 | 1 件 | 0 件 |
| 3 | 37 件 | 0 件 |
| 4 | 1 件 | 0 件 |
| test | 1 件 | 0 件 |

そのうえでボード 1 を実際に起動し、`.jsonl` から履歴 89 件を読めることを
確かめた。**旧 `.json` は 5 つとも残っている。**

### 削除

- `src/ytbg/storage.py` — `_load_old()` / `_old_clock()` / `old_path` を消し、
  `load()` の分岐を 1 本にした。使わなくなった `typing.Any` の import も消した
- `tests/test_save_load.py` — 旧形式を読むテストを消し、
  **「旧形式は読まないし、消しもしない」**と**「旧形式しか無いときは
  初期配置から始まる」**の 2 つに置き換えた
- `CLAUDE.md` / `docs/Admin.md` / `src/ytbg/server.py` の記述を直した

### レビューを受けて足したもの

- **`.json` があるのに読まないときは、ログに 1 行出す。**
  それまでは初回起動とまったく同じ文言で、利用者が気づけなかった
- **`GameInfo.from_dict()` の docstring を直した。** 「旧形式のために
  緩いまま」という理由づけが嘘になっていた。いま `strict=False` が要るのは
  クライアントから届く `set_gameinfo` のため
- **`set_gameinfo` がキーの欠けた dict を受けることのテストを足した。**
  上の理由づけを取り違えて `strict=True` にしても、それまでは
  1 件も落ちなかった（reviewer が変異を注入して実測した）
- `docs/Admin.md` に、**旧ファイルの中身は取り戻せない**こと
  （古い版で一度起動して `.jsonl` へ移すしかない）を書いた

TODO-033 で書いた `docs/Admin.md` の誤り（`/p1` と `/p2` で盤面の向きが
決まる）も、ここで直した。向きは URL では決まらず、Cookie で
ブラウザごと・ボードごとに覚える。

## 分担の振り返り

- **各担当が何を見つけたか。**
  reviewer が、**消したコードそのものではなく「残ったコードの理由づけが
  嘘になった」**ことを見つけた（`GameInfo.from_dict()` の docstring）。
  さらに変異を注入して、その誤読をテストが捕まえられないことまで実測している。
  「旧形式しか無い利用者が黙って初期配置から始まることに気づけない」も
  reviewer。verifier は検証をすべて通し、戻すと落ちること・実際の起動での
  挙動・利用者のファイルが無傷であることを確かめた
- **見込みと食い違ったのはなぜか。**
  見込みは `main + verifier` だったが、**分岐を消す変更なので reviewer を足した。**
  これは正解だった（要修正 2 件はどちらも reviewer が見つけたもので、
  検証はすべて通っている状態だった）。料金は概算 $12.1 で、main が 84%
- **次に同じ規模ならどう組むか。**
  同じ組み方でよい。**「削除だけの項目だから確認だけで足りる」と考えないこと。**
  削除で壊れるのは消したコードではなく、**残ったコードの前提**のほうだった。
  減らせる余地は main 側の cache_creation（74 万）で、これは 1 つの会話で
  TODO-032・033・031 を続けて進めたため。**項目ごとに `/clear` を挟めば、
  ここは大きく減る。**
