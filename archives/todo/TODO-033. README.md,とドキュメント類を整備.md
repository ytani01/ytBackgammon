## 分担の振り返り

- **各担当が何を見つけたか。**
  verifier は、番号バッジと説明文の食い違い、`__init__.py` の抜けを見つけた。
  mermaid を実際にレンダリングして構文を確かめ、`~/ytbg-*.json` を
  壊していないことも確かめている。
  implementer は 3 人とも**利用の上限で落ち、成果ゼロ**だった
- **見込みと食い違ったのはなぜか。**
  見込みは implementer + verifier。3 人並行で起動したのは、
  文書が 4 つあってファイルが重ならないと判断したため。**これが裏目に出た。**
  3 人が同時に走ると消費が 3 倍の速さで進み、**全員が同時に上限に当たって
  全滅した**。1 人ずつなら少なくとも 1 つは仕上がっていた。
  結果として main が 87% を占め、文書はすべて main が書いた
- **次に同じ規模ならどう組むか。**
  **文書を書く項目では、並行数を 2 までにする。** 上限に当たったときに
  全滅しないよう、**仕上がったものから順にコミットできる単位で渡す**
  （1 人が 1 文書を書き終えたら、その時点で管理者がコミットする）。
  また、**この項目は main が書いたほうが安かった可能性が高い**。
  文書の中身は、この会話ですでに読んだコードから書けるもので、
  担当を立てると同じコードを読み直すところから始まる。
  **確認だけを分ける形**（今回の最終形）が、規約にも合っていて安い。
  スクリーンショットのように試行錯誤が要るものは、画像を見ながら
  直す必要があるので、main が手元でやるほうが早い
