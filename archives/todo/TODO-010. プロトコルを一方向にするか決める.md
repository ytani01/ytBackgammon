## きっかけ

TODO-009（Starlette + uvicorn への移行）で通信層を触ったときに、同じ変化を
2 つの経路で伝えていることが目についた。操作系はサーバが `gameinfo` を
更新したうえで**受け取ったメッセージをそのまま全員へ転送**し、受け取った JS が
自分でもう一度同じ操作を適用する。履歴系は `emit_gameinfo()` で状態を丸ごと送る。

結果、**同じ更新ロジックが Python と JS の両方にある**。`CLAUDE.md` の
「`type` を足すときは両方直す」は、この設計の帰結だった。

## やったこと

コードは変えていない。調べて決めただけ。

### 調べたこと

`ytbg.js`（4305 行）の盤面更新ロジックを `Explore` に洗い出させた。
報告は `archives/agents/TODO-010/explore-report.md`。

- **両方に分岐があるのは 8 種類**（`put_checker`、`cube`、`dice`、`set_turn`、
  `set_playername`、`set_score`、`set_clock_limit`、`set_player_clock`）。
  `resign` はサーバだけで JS 側は `set_turn` の `resign` で処理し、
  クロック系の 5 つ（`set_clock_switch`、`resume_clock`、`start_clock`、
  `stop_clock`、`reset_clock`）は JS だけ。`set_gameinfo` は受け口が JS に無い
- **`Board.load_gameinfo()`（`ytbg.js:3531-3618`）は既に盤面を復元できている。**
  ダイスの使用済みフラグも `Dice.disable()` が値に +10 して符号化するので
  `gameinfo.board.dice` に載り、復元される
- **ルール判定は全部 JS 側にある。** `get_dst_points()`、`get_dst_point1()`、
  `check_disable()`、`winner_is()`、`calc_gammon()`、`closeout()`、
  `all_inner()` など。サーバ（`yt_backgammon.py`）にはルール判定が 1 つも無い
- **先行適用は応答性のためではなく、判定のためだった。** `on_mouse_up_xy()` は
  emit した直後に `put_checker()` を先行実行し、その盤面で `check_disable()` と
  `winner_is()` を呼ぶ（`ytbg.js:2557`、`2572`。コメントに理由が書いてある）
- **`gameinfo` に無い状態が 3 つある。** `free_move`（DOM のチェックボックスを
  直読みし、サーバへ送っていない）、`clock_sw`、クロックの動作中フラグ
  （`PlayerClock.active`）。後ろ 2 つは専用のメッセージで転送されるが
  `gameinfo` に無いので、**再接続すると復元されない**
- **クロックはクライアントだけで進む。** `setInterval(update_clock, 200)`
  （`ytbg.js:2766`）。サーバ側に対応するタイマーは無い

### 決めたこと

利用者と相談して 3 つ決めた。

- **受信側だけ一方向にする。** サーバ → クライアントを `gameinfo` ＋直前の
  操作の 1 本にまとめ、`ws.onmessage` の 8 分岐を消す。`type` の二重定義は
  これで解消する
- **「クライアントは描画するだけ」にはしない。** ルール判定をサーバへ移すと
  `yt_backgammon.py` にルールを新規実装することになり、`CLAUDE.md` の
  「ルールチェックは補助であり free move で無効化できる」という方針とも合わない。
  判定は送信前のチェックとして JS に残す
- **先行適用は残す。** 往復を待つと `check_disable()` と `winner_is()` が
  1 手古い盤面で走る。やめるなら `on_mouse_up_xy()` の後半（ダイス消費・
  ヒット処理・勝敗判定）を組み直すことになり、体感にも出る

「自分の操作の反応が遅くなる」という懸念は、着手前に思っていたほど効かない
ことも分かった。**今もほとんどの操作が往復を待っている**（`set_turn` は
ローカル適用の行がコメントアウトされている。`ytbg.js:3093`）。

## 確かめたこと

`Explore` の報告のうち、判断に効く事実は main が原文を見て裏を取った。

- `init_gameinfo()`（`yt_backgammon.py:31-70`）に `free_move`、`clock_sw`、
  クロックの動作中フラグのキーが無いこと
- `Dice.enable()` / `disable()`（`ytbg.js:2038-2049`）が `value % 10` と
  `value % 10 + 10` で使用済みを符号化していること
- `load_gameinfo()` が `history_flag` の偽のときに必ず `stop()` してから
  秒数を入れること（`ytbg.js:3587-3592`）
- `setInterval` が `ytbg.js:2766` の 1 か所だけであること
- `src` を読んでいる箇所がサーバにも JS にも無いこと
