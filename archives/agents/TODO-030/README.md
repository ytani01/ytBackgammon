## main が決めたこと（実装の前提）

### 1. `Board.apply()` を唯一の経路にする

```js
apply(gameinfo, {sec, history_flag, clock_state, last_op})
```

いまの `load_gameinfo()` を土台にしてよい（名前を変えるだけでもよい）。
**表示を変えるのはここだけ**にし、`put_checker()` は消す。

### 2. 先行実行は残す。ただし予測した `gameinfo` を `apply()` に渡す

`Checker.on_mouse_up_xy()` は、**サーバの応答を待たずに反応する**
（共有ボードなので、無いと操作感が悪い）。いまは `put_checker()` を
直接呼んでいるが、これをやめ、**予測した `gameinfo` を作って
`apply()` に渡す。**

- 予測は `this.gameinfo`（`apply()` が受け取った最後のもの）を土台に、
  動かしたチェッカーの `[point, idx]` を書き換えて作る
- **`Position.with_move()` で「動かせるか」を確かめてから**予測を作る
  （TODO-027 で、駒が無ければ例外を投げる形にした）
- **`sn` は書き換えない。** 予測はサーバの通し番号を進めない
- **ヒットのときは 2 手ぶん**（相手をバーへ、自分を移動先へ）。
  いまも `emit_put_checker()` を 2 回呼んでいる

### 3. 予測が外れたときは、サーバの `gameinfo` が上書きする

**これがこの項目でいちばん危ないところ。** 予測どおりでなかった場合、
サーバから届く `gameinfo` で必ず正しい表示に戻ること。

- `apply()` は毎回チェッカーを配り直すので、上書きは成り立つはず
  （TODO-017 で「位置が変わったものだけ動いて見える」形にしてある）
- **確かめ方まで実装担当が用意すること。** わざと外れる予測を作って、
  サーバの応答で表示が戻ることを見るテストを足す

### 4. 先行実行の中の「表示以外」は触らない

`on_mouse_up_xy()` は、チェッカーを置く以外にもやっている。
**次のものは今回の範囲外で、動きを変えない。**

- 使ったダイスを `disable()` にする
- `roll_btn.check_disable()`
- `winner_is()` を見てスコアを上げる、`emit_turn(-1, -1)`
- `emit_msg("dice", ...)`
- free move のときの早期 return

**これらが先行実行の結果（置いたあとの盤面）を見ているなら、
予測した `gameinfo` を反映したあとで呼ぶこと。** 順番が変わると
ダイスの使用済みや勝ち判定がずれる。

### 5. `Board.get_dst_points()` などをルール層へ移すかどうか

TODO-027 で移していない `get_dst_points()` / `get_dst_point1()` /
`all_inner()` は、**この項目では移さない。**
`Position` を使うように書き換えたくなったら、直さずに報告する。
（移すなら別項目にする）

### 6. 挙動は変えない

**盤面の見え方・操作感・送るメッセージを変えない。**
`tests/browser/` の 39 件と `tests/js/` の 59 件を
**1 行も変えずに通すこと。** 直したくなったら挙動が変わった印なので、
直さずに報告する。

### 7. 既知の揺れるテスト

`clicks.test.mjs` の「スコアの ▲ → set_score」は、**この項目より前から
ときどき落ちる**（`819a7b2` でも 5 回中 1 回）。落ちたら同じテストか
確かめて走らせ直す。**他のテストが落ちたらそれは別の話。**
