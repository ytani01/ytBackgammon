# TODO-031 の分担

項目そのものの記録は
[`archives/todo/TODO-031. 旧形式（~_ytbg-{server_id}.json）の読み込みを消す.md`](../../todo/TODO-031.%20旧形式（~_ytbg-{server_id}.json）の読み込みを消す.md)。

## なぜこの分担にしたか

旧形式を読む分岐を消す変更で、**読み込みの挙動が変わる**。
見込みは `main + verifier` だったが、
`~/.claude/CLAUDE.md` の「挙動が変わる項目、分岐や条件式が変わる項目には、
確認の担当とは別にレビューの担当も入れる」に従って reviewer を足した。

| 担当 | モデル | 役割 |
|------|--------|------|
| main | Opus 5 | 移行と実装（削除は小さいので担当を立てなかった） |
| verifier | Sonnet 5（定義のまま） | 検証の実行、戻すと落ちることの再現、実際の起動での確認 |
| reviewer | Opus 5（定義の sonnet から上書き） | 規約と設計に照らしたレビュー |

## 結果

**検証はすべて通っている状態で、reviewer が要修正 2 件を見つけた。**
どちらも「消したコード」ではなく「**残ったコードの前提が嘘になった**」もの。

- `GameInfo.from_dict()` の「旧形式のために緩いまま」という理由づけ。
  reviewer は、この誤読で `strict=True` にしてもテストが 1 件も落ちないことを、
  変異を注入して実測した
- 旧形式しか無いボードを起動しても、利用者が気づけるログが出ない

## 報告

- [verifier-report.md](verifier-report.md) — 検証の結果と実際の起動での確認
- [reviewer-report.md](reviewer-report.md) — 要修正 2 件・検討 4 件

## 進め方で分かったこと

**「削除だけの項目だから確認で足りる」と考えないこと。**
削除で壊れるのは、消したコードではなく残ったコードの前提のほうだった。
