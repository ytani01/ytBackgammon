# TODO-033 の分担

項目そのものの記録は
[`archives/todo/TODO-033. README.md,とドキュメント類を整備.md`](../../todo/TODO-033.%20README.md,とドキュメント類を整備.md)。

## なぜこの分担にしたか

文書が 4 つ（README・Player・Admin・Developer）あり、触るファイルが
重ならないので、**3 人の implementer を並行で起動した**。

| 担当 | モデル | 分担 |
|------|--------|------|
| implementer A | Sonnet 5 | スクリーンショットの生成と `docs/Player.md` |
| implementer B | Sonnet 5 | `README.md` と `docs/Admin.md` |
| implementer C | Opus 5 | `docs/Developer.md`（構成の理解が要るため上書き） |
| verifier | Sonnet 5 | 書いたコマンドの再現と、実装との突き合わせ |

## 結果

**3 人とも、利用の上限に当たって途中で落ちた。ファイルは 1 つも
書かれていない。** 並行して走らせたぶん消費が速く進み、全員が同時に
止まった。

文書とスクリーンショットのスクリプトは、そのあと main がすべて書いた。
確認だけを verifier に分けた（規約どおり、書いた本人とは別の目で見る）。

## 報告

- [verifier-report.md](verifier-report.md) — 検証の結果と、指摘 2 件

## 進め方で分かったこと

- **文書を書く項目で担当を並行させるなら、2 人までにする。**
  上限に当たったときに全滅する
- **仕上がったものから順にコミットできる単位で渡す。**
  1 文書ずつ渡していれば、落ちても書けた分は残った
- **この項目は main が書くほうが安かった。** 文書の中身は、
  同じ会話ですでに読んだコードから書ける。担当を立てると、
  同じコードを読み直すところから始まる
